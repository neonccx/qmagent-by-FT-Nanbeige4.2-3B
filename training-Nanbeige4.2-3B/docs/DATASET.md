# QCal Agent Dataset 1.0.0

This is the frozen, training-ready synthetic dataset used for the QCal Agent
1.0 LoRA run. Download the archive and checksums from the
[`dataset-v1.0.0` GitHub Release](https://github.com/neonccx/qcal-agent/releases/tag/dataset-v1.0.0).

## Contents

| File | Purpose | Records |
|---|---|---:|
| `train.jsonl` | LoRA training | 4,637 |
| `validation.jsonl` | Training-time validation | 782 |
| `test.jsonl` | Frozen in-distribution evaluation | 511 |
| `ood.jsonl` | Frozen out-of-distribution evaluation | 986 |
| `manifest.json` | Split membership, provenance and hashes | — |
| `tokenizer_audit.json` | Tokenizer compatibility audit | — |
| `SHA256SUMS` | Per-file checksums | — |

Each JSONL record contains one constrained next-action example: a system
instruction, observable controller context and one assistant native tool call.
The published test and OOD records are evaluation-only and must not be used for
training or model selection.

## Scope and provenance

The records were generated from QCal Agent's deterministic controller and
physics-inspired simulator. They are **synthetic single-qubit calibration
data**, not measurements from a real quantum processor. They provide examples
for S21, Power2D, ZPA2D, spectroscopy, Rabi, Ramsey, T1, Echo, IQraw and the
project's single-qubit XEB proxy. They contain no coupler or two-qubit
calibration evidence.

The training-ready archive omits the separate 256 MB content-addressed raw
trajectory artifact store. The JSONL records, split manifest and hashes are
sufficient to reproduce the released LoRA training inputs and frozen
evaluations; regenerate raw simulator artifacts with the repository scripts
when auditing acquisition provenance.

## Rebuild and audit

```bash
python training/build_dataset.py --devices 64 --output dataset
python training/build_complete_workflow_dataset.py \
  --source dataset --output dataset_complete
python training/audit_dataset.py dataset_complete
python training/audit_tokens.py \
  --dataset dataset_complete --model /path/to/Nanbeige4.2-3B
```

Exact regenerated bytes depend on the recorded seeds, source revision and
generation parameters in `manifest.json`. Always verify `SHA256SUMS` before
training.
